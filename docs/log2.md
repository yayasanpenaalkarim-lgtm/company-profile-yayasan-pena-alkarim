### Compatibility and version rationale

I rechecked the published npm metadata using read-only npm view commands.

| Component | Selected version | Verified compatibility and rationale |
|---|---|---|
| Astro | 5.18.2 | Existing locked version. Avoids combining adapter migration with an Astro upgrade. |
| Cloudflare adapter | 12.6.13 | Declares peer dependency astro: ^5.7.0; Astro 5.18.2 satisfies it. |
| Wrangler | 4.59.2 | The selected adapter itself declares exactly wrangler: 4.59.2. A direct pin uses the same CLI version for future local and CI commands. |
| Supabase client | 2.118.0 | Existing locked version; declares Node >=22.0.0. |
| Node | 22.23.4 | Satisfies Astro, Supabase, and Wrangler requirements; provides an exact local runtime pin. |

Wrangler 4.59.2 declares:

{
  "engines": {
    "node": ">=20.0.0"
  },
  "peerDependencies": {
    "@cloudflare/workers-types": "^4.20260114.0"
  }
}

The adapter depends on:

{
  "wrangler": "4.59.2",
  "@cloudflare/workers-types": "^4.20260116.0"
}

Those Workers type ranges overlap. The generated dependency graph still needs installation-time verification.

Why this Wrangler version: it aligns with the selected adapter’s own exact tooling dependency and avoids introducing a second, independently selected Wrangler version during migration. Adding it directly also prevents later commands from relying on a transient or globally installed CLI.

Limitation: this is a compatibility choice, not a claim that Wrangler 4.59.2 is the newest or free of known vulnerabilities. Dependency advisory review remains an implementation acceptance check. Any necessary tooling upgrade should be explicit and tested rather than silently selecting latest.

### Reasons and risks

| Change | Reason | Risk and control |
|---|---|---|
| Remove Vercel adapter | Its generated deployment target does not match the intended Cloudflare Workers target. | Vercel deployment output will no longer be generated. Restore the baseline adapter/configuration if reverting locally. |
| Select Cloudflare adapter | Generate a Workers-compatible SSR bundle. | Workers runtime behavior can differ from Vercel. Runtime verification belongs to subsequent phases. |
| Pin Astro | Preserve the application’s current framework version during migration. | Future patches require deliberate updates. |
| Pin Supabase client | Preserve the already locked client version while preventing incidental resolution changes. | This does not address database/schema problems or prove Workers runtime compatibility. |
| Pin Wrangler | Align CLI behavior with the adapter’s bundled tooling version. | Older tooling may have defects/advisories; review findings before acceptance. |
| Add Node engine and .nvmrc | Make the Node requirement explicit and local selection reproducible. | Developers must switch runtimes. engines may only warn; .nvmrc requires compatible version-manager usage. |
| Regenerate lockfile | Make clean installs reproduce the approved dependency graph. | Platform packages and transitive dependencies can create a substantial diff; review changes rather than deleting the lockfile and resolving everything anew. |

The Cloudflare v12 adapter enables its default SESSION KV driver. Phase 1 does not create a namespace or add bindings. That configuration remains Phase 2 work, so Phase 1 must not be described as deployment-ready.

The current shell uses Node 26.12.1 and npm 11.20.0. Later validation should use the proposed Node 22 environment, not the current shell.
